# CI/CD pipeline, native packaging, and commercialization for 알비연 링크

This change ships the deployment and commercialization layer for the ROTC business network platform. It adds GitHub Actions CI/CD (build-on-PR, deploy-on-push-to-main via Vercel and Convex), configures Android release signing and iOS archive scripts with Fastlane metadata, and rounds out the product with legal pages (이용약관, 개인정보처리방침), Sentry error tracking, security headers, and SEO structured data. The approach is configuration-heavy and additive — no existing behavior is modified, just new wiring layered on top.

Watch for: the manifest `related_applications` references a different app ID (`com.rotcbiz.link`) than the actual Capacitor/Android config (`kr.albiyeon.link`) (confirmed); `keystore.properties` is not gitignored, meaning production signing credentials could be accidentally committed (confirmed); the deploy workflow's `pnpm build` step produces an artifact that is never deployed — Vercel rebuilds independently (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The deploy workflow runs `pnpm build` then separately invokes `vercel build --prod`. The Vercel step pulls its own env vars and rebuilds from scratch, so the earlier `pnpm build` output in `dist/` is dead code. Worse, if `.env.production` were ever removed from the repo, that step would fail because `VITE_CONVEX_URL` isn't supplied by the workflow environment. The CI workflow already validates build success on the same push, making the deploy workflow's build step purely redundant.

The Android release signing config uses a two-tier fallback (file-based `keystore.properties` then env vars), but `keystore.properties` has no gitignore rule. The `android/.gitignore` has `*.jks` and `*.keystore` commented out. A developer who follows the example file will commit plaintext signing passwords.

The manifest's `related_applications` section uses `com.rotcbiz.link` for Play Store but the actual Android app ID is `kr.albiyeon.link` everywhere else (Capacitor, Gradle). This mismatch breaks Chrome's native app detection and install prompt suppression.

`sourcemap: true` in vite.config.ts deploys `.map` files publicly to Vercel, exposing the full TypeScript source. For Sentry integration, `'hidden'` source maps are the standard pattern — generated for upload but not referenced in the served JS.

The splash screen is removed synchronously after `createRoot(...).render(...)`, but React 19's render is non-blocking. The splash fades before the tree has committed, causing a blank gap on slow initial loads.

## Deploy workflow double-build

The deploy workflow runs `pnpm build` (step "Build") and then separately runs `vercel build --prod`. The Vercel build pulls environment variables via `vercel pull`, which hydrates `.vercel/.env.production.local` — but that happens *after* the standalone `pnpm build`. The standalone build relies on `VITE_CONVEX_URL` being available at compile time (Vite inlines `import.meta.env` values).

```yaml
- name: Build
  run: pnpm build          # <-- uses .env.production from repo

- name: Deploy to Vercel
  run: |
    npx vercel pull ...    # pulls env vars into .vercel/
    npx vercel build ...   # rebuilds from scratch with Vercel's env
    npx vercel deploy ...  # deploys vercel's build, not the earlier pnpm build
```

The `pnpm build` output in `dist/` is never used — Vercel rebuilds into `.vercel/output`. This step only validates that the build succeeds, which is already covered by the CI workflow on the same push event. If `.env.production` is ever removed from the repo (it commits a production Convex URL), the deploy workflow breaks while nothing functionally changes in the deploy.

## Signing credentials exposure

The `build.gradle` references `keystoreProperties` loaded from `android/keystore.properties`. The example file instructs "Do NOT commit keystore.properties to version control" but no gitignore rule enforces this:

```
# Keystore files
# Uncomment the following lines if you do not want to check your keystore files in.
#*.jks
#*.keystore
```

A developer who copies the example and fills in real values will commit the passwords unless they manually edit `.gitignore`. The fix: uncomment the keystore lines and add an explicit `keystore.properties` exclusion.

## Manifest related_applications ID mismatch

```json
"related_applications": [
  { "platform": "play", "id": "com.rotcbiz.link" },
  ...
]
```

`capacitor.config.ts` and `build.gradle` both use `kr.albiyeon.link`. Chrome uses this field for app install prompts and the "already installed" check. A mismatch means the browser won't suppress the PWA install banner for users who have the native app installed, defeating the purpose of `related_applications`.

## Source maps public by default

```ts
build: {
  sourcemap: true,
```

This generates `.map` files alongside every JS chunk in `dist/`. Vercel serves them at their public URL. Anyone can download the source maps and reconstruct the original TypeScript source. For a production app with Sentry, the correct pattern is `sourcemap: 'hidden'` — this produces map files for upload to Sentry's artifact system via `sentry-cli` but excludes the `//# sourceMappingURL` comment, so browsers don't know the maps exist.

## Splash removal timing

```ts
createRoot(document.getElementById('root')!).render(...)
removeSplash()
```

React 19's `createRoot().render()` is non-blocking — it schedules a render but doesn't guarantee the DOM has committed when `render()` returns. The splash fades out immediately (via a CSS opacity transition), but the React tree may not have painted yet. On slow connections where the Convex client initializes asynchronously, the user sees a blank screen between splash removal and first meaningful paint. Moving `removeSplash()` to a `useEffect` in `<App>` would guarantee the component tree has mounted before the splash disappears.
