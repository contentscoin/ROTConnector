# CI/CD pipeline, native packaging, and commercialization for 알비연 링크

This change ships the deployment and commercialization layer for the ROTC business network platform. It adds GitHub Actions CI/CD (build-on-PR, deploy-on-push-to-main via Vercel and Convex), configures Android release signing and iOS archive scripts with Fastlane metadata, and rounds out the product with legal pages (이용약관, 개인정보처리방침), Sentry error tracking, security headers, and SEO structured data. All five issues from the v1 review have been resolved: the manifest app ID is corrected, keystore.properties is gitignored at both levels, the redundant build step is removed from deploy.yml, splash removal is deferred to a useEffect, and source maps are set to `'hidden'`.

Watch for: `robots.txt` references a sitemap at `/sitemap.xml` that doesn't exist and no generation mechanism is in place — crawlers will get a 404 every visit (confirmed); the `replaysOnErrorSampleRate: 1.0` in Sentry config references the Session Replay integration but that integration is never added, so this config line is silently ignored (confirmed); the security headers omit `Content-Security-Policy` and `Strict-Transport-Security`, leaving the app without XSS mitigation and relying entirely on Vercel's default HSTS behavior (likely).

**Verdict**: APPROVED

## High-level view

The deploy pipeline is clean — a single Vercel build-and-deploy step with Convex deployed separately. CI validates build on PRs, deploy runs on main push.

The security headers add nosniff, DENY framing, referrer policy, and permissions policy but omit CSP and HSTS. For a Convex-backed SPA that makes cross-origin requests to `*.convex.cloud` and potentially Firebase, adding a CSP requires care to whitelist those origins. Not blocking for initial launch since all scripts are served same-origin via Vite bundling, but worth adding before the app renders any user-generated content.

The `replaysOnErrorSampleRate: 1.0` config in `sentry.ts` references a replay integration that isn't wired up (no `Sentry.replayIntegration()` in the `integrations` array), making it dead config — no data leakage, just a misleading setting that a future developer might assume is functional.

The `robots.txt` declares a sitemap URL that returns 404. Search engines will record this as a broken reference on every crawl cycle.

## Sitemap reference without backing file

```
Sitemap: https://rotconnector.vercel.app/sitemap.xml
```

No `sitemap.xml` exists in `public/`. The vercel.json rewrite only matches extensionless paths (`/((?!.*\.).*)`), so `/sitemap.xml` will 404 rather than serve `index.html`. Google Search Console will flag this on every crawl.

The public routes are few and static: `/`, `/about`, `/terms`, `/privacy`, `/community`. A static `public/sitemap.xml` listing these is sufficient. If dynamic content (member profiles, events) should be indexed later, a build-time generator would be needed.

## Sentry replay integration gap

```ts
Sentry.init({
  dsn,
  environment: import.meta.env.MODE,
  integrations: [Sentry.browserTracingIntegration()],
  tracesSampleRate: 0.2,
  replaysSessionSampleRate: 0,
  replaysOnErrorSampleRate: 1.0,
})
```

The `replaysOnErrorSampleRate` and `replaysSessionSampleRate` options only take effect when `Sentry.replayIntegration()` is present in the `integrations` array. Without it, Sentry's SDK ignores these values silently. A developer reading this code would reasonably assume error replays are being captured when they're not. Either wire up the integration (adds ~50KB to the Sentry chunk) or remove the two replay lines.

## Security headers — CSP gap

For this app, a minimal effective CSP would look like:

```
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; connect-src 'self' https://*.convex.cloud https://*.ingest.sentry.io; img-src 'self' data:; font-src 'self';
```

The `'unsafe-inline'` for styles is required because Tailwind CSS v4 with the Vite plugin generates inline `<style>` blocks. The JSON-LD `<script type="application/ld+json">` in `index.html` is not executed as JavaScript so doesn't require a nonce.

Not blocking for launch — the app doesn't render user-supplied HTML and all scripts are bundled same-origin — but should be added before announcements or other user content can include HTML/markdown rendered without sanitization.
